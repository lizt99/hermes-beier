# Project Shang-An Content Research SOP

## When to use
Use before generating content for Project Shang-An.

## Goal
Improve content quality and value density so content stays aligned with the PRD's growth goal.

## Rule
Do **research first, then write**.
Do not rely on Xiaohongshu/Douyin browser access as a prerequisite.

## Fixed sequence
1. Read the PRD / SOP if the topic direction is not already locked.
2. Check internal evidence first:
   - historical post performance
   - comments / DMs / user wording
   - existing title / script / case / risk assets
3. Check external public sources if internal evidence is weak:
   - searchable public web pages
   - forum / Q&A / article pages
   - official policy / bank / legal public information
4. Lock four items before writing:
   - what to post
   - for whom
   - target action
   - core value point
5. Then generate the publish-ready content package.

## Minimum output before writing
State these clearly:
- topic
- audience
- target action
- evidence basis

## Notes
- Platform direct browsing is optional, not required.
- Prefer practical, tool-based, template-based, and actionable content over pure emotional content.
- Avoid over-promising and risky wording.
- Keep the workflow minimal; do not add unnecessary steps.
- If browser-based platform or search research is blocked by captcha / anti-spider / empty pages, explicitly say so and fall back to PRD + internal evidence + accessible public web sources.
- When external browsing evidence is weak, do not overstate the strength of the browser research; separate “browser-confirmed” from “PRD-derived” conclusions.
- For persona redesign tasks, review the PRD audiences again and decide which single audience should be primary for the current account before proposing profile fields.
