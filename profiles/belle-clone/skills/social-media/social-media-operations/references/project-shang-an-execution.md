## Canonical operating flywheel
痛点/冲突内容拉新 → 工具/清单内容促收藏 → 实操/模板内容促关注 → 评论关键词/私信承接需求 → 直播/答疑/轻服务加深信任 → 筛选高意向用户 → 沉淀问题库/案例库/话术库 → 反向验证低效内容与风险表达 → 优化标题、选题、封面、承接口径 → 产出下一轮更精准内容

## Module checklist
1. 流量入口: attract real debt users, not spectators.
2. 信任建立: strengthen save/follow and account authenticity.
3. 互动承接: turn comments/DMs into structured demand samples.
4. 需求归档: archive repeated questions by audience/stage/problem type.
5. 资产沉淀: titles, scripts, cases, risk wording, visuals, mother templates.
6. 转化筛选: identify high-intent users without rushing conversion.
7. 反向验证: check pseudo-growth, risk, audience quality, persona drift weekly.
8. 放大复制: scale repeatable winners by angle/title/cover/audience variation.

## Triggered proactive follow-up
Belle should proactively initiate follow-up when daily, post-publish, weekly, abnormality, or scaling triggers are met.

Request only the smallest useful input set, such as:
- yesterday's content ID/title/platform
- early performance numbers
- representative comments and DMs
- whether the owner modified the draft before posting
- any warning, risk, or subjective discomfort

## Review logic
- high play + low save = emotional爽文, insufficient value
- high save + low follow = useful tool, weak persona
- high comment + low DM = discussion traffic, weak precision
- high DM + low valid dialogue = weak intake wording or wrong diversion

## Decision framework
Classify each item as:
- Scale
- Hold
- Optimize
- Stop

Bottleneck shortcuts:
- exposure weak → fix topic/title/cover
- save weak → fix usefulness/value density
- follow weak → fix persona/trust continuity
- DM weak → fix intake design/CTA precision
- valid dialogue weak → fix DM segmentation and response wording

## Pitfalls
- confusing attention with demand quality
- skipping reverse verification
- drifting into conversion too early
- implying Belle publishes directly
- using generic platform advice instead of project language
- waiting passively when the next follow-up is obvious
- asking broad unfocused questions
